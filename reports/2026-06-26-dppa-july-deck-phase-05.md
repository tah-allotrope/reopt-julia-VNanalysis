## What's in the [repo-checked] deck

The injector places a structured `[Repo check]` block at the bottom of
each slide's speaker notes, separated from any author notes above by
the delimiter `=== [Repo check] (generated) ===`. Each block lists:

- The check id + slide + bucket
- The claim (verbatim from the deck)
- The deck value + unit + citation
- The repo value + delta (%)
- The repo function + source reference
- Any assumptions used
- The takeaway (verdict rationale)

Sample (Slide 23, Case 5 metrics — 8 checks, ~7,500 chars):

```
[Repo check] Slide 23 — 8 check(s) + 0 known gap(s)
Source: reports\dppa_july_2026_repo_check.json (orchestrator + plan).
Generated by scripts/python/integration/ceba_deck/inject_repo_notes.py --deck july.

--- checks ---
🔧 J_B06_case5_seller_irr  (slide 23, bucket B)
  claim     : Case 5 (Solar + Large BESS) — Seller equity IRR (aftertax/levered)
  deck      : 0.169 fraction
  repo      : 0.1671
  delta     : -1.10%
  repo fn   : reopt_pysam_vn.pysam.single_owner.run_single_owner_model (solved CAPEX, calibrated BESS)
  assumed   : BESS energy pinned to 7.5 MWh (~$160/kWh × 7,500 kWh ≈ $1.2M replacement, DEC-004).
  assumed   : CAPEX back-solved by 1-D root find on installed_cost_usd to hit deck IRR (DEC-001).
  assumed   : Solar sized to ~85% of factory 9,750 MWh/yr load (≈ 5.25 MWp at 18% CF; Q-001 default).
```
