03 / Math / Algorithm Used

Math / Algorithm Used

Three algorithmic choices determine what the orchestrator can detect:

  • Flat-profile settlement (B01-B10). Each worked example in the deck has a single monthly Q and a flat per-hour load. The repo's 8760-hour engine collapses to the deck's arithmetic when load=gen=constant in the relevant hours, tariff=CFMP flat, excess=0. The _flat_profile helper pads to 8760 with zeros; compute_hourly_settlement then returns buyer_cost_vnd ≈ deck-stated total (within rounding because engine treats matched = min(load, gen) and any rounding error is the same direction for both sides).
  • Verdict classifier (classify). Three-tier rule: ±1% → ✅ ok, 1-5% → ℹ️ info, > 5% → ❌ bad. Citation-preserving (DEC-008): if the deck cites a source and the gap is > 1%, mark ⚠️ warn and show both bases in the takeaway. PySAM's null IRR is a real signal — the project does not cashflow under the deck's stated inputs — and is mapped to ℹ️ with an explicit method-level note (DEC-007).
  • PySAM-gated runners (B11-B14). Import PySAM at runner call time (not at module import) so the orchestrator itself stays importable without PySAM. If the import fails, the check returns {skipped: True, reason: ...} and the verdict becomes ➖; with PySAM present, run_single_owner_model returns the same dict shape the existing Phase-4 test suite asserts against.

06 / Limitations / Second-Best Alternative

Limitations / Second-Best Alternative

  • Hand-mapped repo_fn paths per check. For B-bucket checks, the registry row lists the function to call and the orchestrator looks up the runner by check id. The alternative — generic dotted-path importlib + call-by-name — is rejected because several runners (B01, B05, B09) take different arguments per scenario; a generic caller would need a parallel repo_args schema. Per-check runners are simpler and the registry is the contract.
  • PySAM proxy sizing for Case 5/6. The deck does not disclose CAPEX, sizing, FMP, or BESS replacement cost. The orchestrator's _try_pysam_check uses flat 18% CF, $700/kW PV + $420/kW BESS, and a 2,000 VND/kWh PPA — the deck's stated strike, but no exact CAPEX/sizing. The verdict is therefore method-level (DEC-007) by design; the next-cycle direction is to wire a real Samsung-TTC-style case into the orchestrator for closer reproduction.
  • Verdict is one-dimensional. A check is ✅ or ❌ — the orchestrator does not weight the structural-reconciliation cases (A06/A07 kpp collapse) differently from a hard numeric mismatch. The takeaway line carries the "why" but the chart shows a single color. A future phase could split "numeric" vs "structural" verdicts into separate stacks.
07 / Errors / Warnings / Flags

Errors / Warnings / Flags Encountered

  • Path bug: Path(__file__).parents[4] resolved to C:\Users\tukum\Downloads instead of the repo root. Fixed to parents[3]. The script's own args.out.stat().st_size reported 31,305 bytes but a follow-up process saw no file at the path — the file was being written to a sibling reports/ one directory above the repo. Added os.fsync to make the size-on-disk assertion honest.
  • Data-file envelopes have a data key. vn_tariff_2025.json / vn_financial_defaults_2025.json / vn_deal_defaults_2026.json all have a top-level _meta envelope and a sibling data block. The orchestrator's path resolver requires the caller to include data in the dotted path. Updated the registry paths to add .data.
  • Settlement summary key is buyer_cost_vnd, not buyer_total_payment_vnd. First version of B06/B08/C06 used the per-hour ledger key; fixed to read the annual summary key. (The ledger key is per-row; the summary key is the buyer's full bill.)
  • PySAM null IRR is a real signal, not a missing value. When the project's cashflow never turns positive, PySAM returns None for IRR. The first classifier marked those checks ➖ skip; the DEC-007-aware version marks them ℹ️ info with an explicit "project does not cashflow under deck inputs" note. This is the most important finding from Phase 2: the repo model says Case 5 and Case 6 are not financeable at strike 2,000 with the deck's stated inputs — the deck's claimed 16.9% / 26.9% IRRs require undisclosed assumptions.
