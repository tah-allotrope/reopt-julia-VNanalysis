03 / Math / Algorithm Used

Math / Algorithm Used

Three structural choices matter for the injector:

  • Copy-then-modify, never modify in place. Each run deletes the existing copy (if any) and shutil.copy2s the source before opening. The source mtime stays at its original value (verified: source mtime preserved across runs, output mtime is "now"). This is the "Phase 4 exit criterion: The original .pptx mtime is unchanged after a run."
  • Idempotent replace via a single delimiter. === [Repo check] (generated) === is the marker. The replace function splits on the delimiter: keep everything above, replace everything below. If the delimiter is absent, the new block is appended below any existing author notes. If the slide has no notes slide, slide.notes_slide lazily creates one.
  • Per-slide block composition. For each slide, gather every check where check["slide"] == slide_idx and every known_gap where gap["slide"] == slide_idx. Each check renders as a 6-12 line block (verdict icon + id + slide/bucket, claim, deck value, repo value, optional delta, repo_fn + file:line, optional assumptions, takeaway, optional extras). This is the per-slide colleague-facing summary; the markdown is the per-bucket table, the JSON is the raw data, and the deck notes are the in-context review surface.

06 / Limitations / Second-Best Alternative

Limitations / Second-Best Alternative

  • Notes are text-only, not styled. python-pptx 1.0.2 doesn't expose rich-text styling on the notes slide. The same verdict icon + id block renders as monospaced Courier. That's fine for a colleague reading in the Notes pane of PowerPoint; not great for an "at-a-glance" review view. The alternative — drop a separate HTML review file alongside the deck — was rejected because the goal is in-deck review.
  • Block length on B-bucket PySAM slides is ~2 KB. Slides 24 / 25 each have 3 checks (B11/B12/C04 or B13/B14/C04) with full PySAM numbers in the extras. Still readable but a colleague scanning Notes pane may need to scroll. A future cycle could shorten the extras block to the headline number only.
  • No slide-level aggregation of "this is the headline finding." Each slide's block is the per-check detail. A future cycle could add a slide-header summary line ("This slide's 3 checks: 1 ✅, 1 ❌, 1 ℹ️; see kpp collapse structural note.") so colleagues see the headline before the detail.
