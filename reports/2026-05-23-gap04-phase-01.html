03 / Math / Algorithm Used

Math / Algorithm Used

  • Virtual CfD hourly settlement: buyer_total = (matched × FMP × KPP) + (matched × adder) + (shortfall × retail) + matched × (strike − FMP). When excess_treatment = cfd_on_excess, the CfD term extends to excess generation.
  • Private wire hourly settlement: buyer_total = (matched × strike) + (shortfall × retail). No CfD component, no KPP, no DPPA adder. Developer revenue = matched × strike + exported × surplus rate.
  • Export cap: Decree 57 limits export to a fraction of total generation per hour: max_export = gen × export_cap_pct / 100. Excess beyond cap is curtailed.
  • KPP conversion: kpp_factor = 1.0 + kpp_pct / 100, e.g. 2.7263% → 1.027263 multiplier on market-price payments.
  • Blended rate: buyer_blended = buyer_cost_vnd / total_load_kwh. Zero-load returns 0.0.
  • Buyer benchmark: evn_only_cost = ∑ (loadh × tariffh) for all 8760 hours. Savings = benchmark − buyer_cost.

06 / Limitations

Limitations / Second-Best Alternative

  • No multi-year cashflow projection: The settlement engine computes year-one hourly settlement only. Multi-year escalated cashflows (as in dppa_settlement.py::project_dppa_cashflows()) are out of scope for this phase but could be added in a future phase.
  • Excess treatment “cfd_on_excess” is a stress case: This mode exists to quantify the buyer’s worst-case exposure when CfD terms apply to excess generation. It is not a recommended contract structure.
  • No BESS incentive qualification check: The private-wire mode does not verify whether battery parameters qualify for the higher ceiling tariff (as Case 1 does). This is a site-specific check that belongs in the calling code.
  • Alternative considered: Wrapping existing case functions with adapter layers instead of extraction. Rejected because the existing functions have hardcoded paths and ninhsim-specific assumptions that make them non-reusable without modification.
