03 / Math / Algorithm Used

Math / Algorithm Used

  • Linear interpolation for missing values: For each gap at index i, find nearest non-null left neighbor L and right neighbor R. Fill with (L + R) / 2. Edge gaps use nearest available neighbor. All-null series raises ValueError.
  • Negative clipping: Values below zero are replaced with 0.0 before interpolation, preventing negative loads from distorting gap-fill averages.
  • Multi-sheet scanning: Each sheet is scored: +100 if row count = 8760, +50 if 35040 or 17520, +50 if any header matches load-column patterns. Highest-scoring sheet is selected.
  • Column auto-detection: Headers are normalized to lowercase with underscores, then matched against patterns: load_kw, load, demand, consumption, kw, demand_kw, power, energy. Falls back to first column.
  • JSON path search: Priority order: ElectricLoad.loads_kw → top-level loads_kw → explicit column_hint → any 8760-length list → one-level-deep nested 8760-length list → root array.

06 / Limitations / Second-Best Alternative

Limitations / Second-Best Alternative

  • No resampling yet: Files with non-8760 row counts (15-min, 30-min, monthly) raise LoadLengthError with a resolution hint. Resampling and synthesis are deferred to PHASE-03.
  • Original scripts unchanged: rank_case_study_offtakers.py retains its own copy of the cleaning functions. Both copies are equivalent but not shared. This is intentional to avoid breaking existing workflows.
  • Column auto-detection heuristic: Non-English headers (e.g., Vietnamese column names) may not match the pattern list. Explicit column_hint parameter is the workaround.
  • Multi-sheet scanning is best-effort: If multiple sheets have 8760 rows with load-like headers, the first highest-scoring sheet wins. No disambiguation prompt.
  • Second-best alternative: Continue writing per-factory extraction scripts. Not chosen because it does not scale for client demos and creates maintenance burden.
