01 / Executive Summary

Executive Summary

What was wrong

The repository's CI workflow has reported red on every push since it was added on 2026-07-15 — 22 test failures on the most recent run, out of a suite of roughly 600. No pytest marker actually excluded anything (the workflow filtered on a network marker that no test carried), PySAM was unpinned in CI and resolved to a version whose API had drifted from the one used locally, and five webapp tests failed only in CI because they depended on a git-ignored credentials file that is deliberately absent there. Separately, ~433 MB of stale git worktrees from earlier agent sessions — checkouts of branches with zero commits beyond main — sat unused in the working tree.

What was done

Four pytest markers (network, requires_artifacts, golden_machine, and a newly-justified requires_julia) now honestly partition the suite into what CI can and cannot run, and are actually applied to the right tests rather than only declared. PySAM is pinned in CI to the exact version used locally. Webapp tests no longer depend on a real API key. Every one of the five long-standing local test failures now carries a specific, dated reason rather than sitting as an unexplained red. Four zero-value git worktrees and two orphaned stub directories were removed, reclaiming essentially all of the ~433 MB with zero loss of work (verified clean and zero-commits-ahead before deletion).

02 / Background & Objective

Background & Objective

reopt-pysam-vn models solar/wind/storage/DPPA project economics for Vietnam using NREL REopt.jl plus PySAM. Four consecutive analysis passes over the prior eleven days (2026-07-11 through 2026-07-18) converged on the same conclusion: the repository does not primarily need new ideas, it needs an already-diagnosed backlog executed. The most recent pass (2026-07-22) independently re-verified with live tools — gh run list, gh run view --log, ruff check --statistics, git worktree list — that CI was still exactly as red as previously documented, that the repository's lint-violation count had grown from 181 to 206 in four days, and that ~433 MB of stale worktrees had never been cleaned up. That brainstorm became a five-phase plan (plans/2026-07-22-ci-truth-correctness-sprint-plan.md); this report covers execution of its first two phases — workspace hygiene and a genuinely green CI gate — which the plan itself frames as the precondition every later architectural initiative in this repository declares for itself.

04 / Assumptions & Constraints

Assumptions & Constraints

Assumptions carried into implementation

  • The locally-installed PySAM version (7.1.0, confirmed via PySAM.__version__ and pip show nrel-pysam) is the correct version to pin CI to
  • The four worktree branches removed in PHASE-01 (cranky-torvalds-3f262a, dazzling-northcutt-0807cc, unruffled-banzai-88ae43, upbeat-almeida-53c200) genuinely carried zero commits beyond main — verified directly via git log main..<branch> for all four immediately before deletion, not assumed from the earlier brainstorm alone
  • No other session was concurrently using any of the four worktrees — inferred from each having a clean working tree with no in-progress edits

Constraints honored throughout

  • Samsung/TTC bit-exact parity: examples/samsung-ttc_combined-decision.example.json was never edited; the parity test module is excluded from CI via the new golden_machine marker rather than weakened
  • git worktree remove was never forced (--force) — its default refusal on a dirty tree was treated as the real safety net, not just the pre-check
  • Every xfail applied to a previously-red test used strict=False with a specific, dated reason string, so a future fix shows as an unexpected pass rather than disappearing silently
05 / Methodology

Methodology

Every classification decision in this effort was backed by direct evidence gathered in this session, not assumed from the source plan. Before deleting any git worktree, its branch history and working-tree cleanliness were re-checked live. Before marking the two failing test_regime_engine_smoke.py tests, the underlying regime_runner.build_regime_matrix source was read directly, which revealed they shell out to a real local Julia subprocess regardless of a solve=False flag and write to pytest's isolated tmp_path rather than the repository's tracked artifacts/ directory — meaning the plan's anticipated requires_artifacts label would have been factually wrong for this pair, and a new, honestly-named requires_julia marker was introduced instead, consistent with this repository's standing decision to keep Julia out of CI. Before marking the two Samsung/TTC parity divergences as pre-existing rather than a regression, a temporary git worktree was checked out at commit fd8ceaf (the last commit before the webapp phase-1/phase-2 sessions) and the same test re-run there — it failed with the identical numeric divergence, which is direct evidence the issue predates that work rather than an assumption. A newly written repo-invariants test was deliberately run before its corresponding fix landed, to confirm it failed for the right reason and with the right file list, and again afterward to confirm it passed — a small test-the-test discipline applied throughout.

06 / Phase-by-Phase Analysis

Phase-by-Phase Analysis

Done  Phase 1 — Workspace Hygiene

Four registered git worktrees under .claude/worktrees/ (108–109 MB each) were re-verified clean and zero-commits-ahead of main, then removed with git worktree remove; two 8 KB orphaned stub directories were pruned. The four corresponding local branches were deleted with git branch -d (which refuses on unmerged history, making the deletion self-verifying). Done  Phase 2 — CI Truth

Registered network, requires_artifacts, golden_machine, and requires_julia pytest markers and applied every one of them to the specific tests that actually need it — 9, 3, 2, and 4 tests respectively, each verified by exact --collect-only count. Added a new repo-invariants test module enforcing the flat-script ban, the no-tracked-artifacts rule, and (with a deliberate tripwire xfail) the no-root-binaries rule. Relocated the two remaining flat scripts to their canonical subdirectories, fixing each script's repo-root path math for the new depth.

Not started  Phase 3 — Security & Hygiene

Untracking the three deck .pptx binaries and two root PNGs, fixing the broken .gitignore bracket-glob patterns, removing the redundant requirements.txt, and documenting the still-open NREL key rotation requirement remain queued exactly as specified in the source plan.

Not started  Phases 4–5 — Tariff Fix & Single Owner Audit

07 / Findings & Recommendation

Findings & Recommendation

Finding 1 — the CI gate's exclusions are now real, not aspirational. Before this effort, ci.yml filtered on a network marker that zero tests carried, meaning the filter silently selected everything. The gate now has four markers, each verified by exact collection count to match only the tests that genuinely need it, and a local simulation of CI's precise filter runs clean.

Finding 2 — one test-classification decision changed the plan's own labeling, based on evidence gathered during execution. The source plan anticipated marking test_regime_engine_smoke.py's two failures requires_artifacts. Reading the underlying implementation showed they depend on a local Julia executable, not on the tracked artifacts/ directory. Mislabeling them would have been a smaller version of the same "documentation doesn't enforce itself" problem this whole sprint exists to fix, so a fourth, honestly-named marker was added instead.

Finding 3 — the Samsung/TTC parity divergence is confirmed pre-existing, not a regression. A direct re-run at a commit predating the webapp sessions reproduced the identical numeric divergence, which rules out those sessions as the cause without needing to assume it from documentation alone. The golden file was not touched.

Recommendation. Push these two phases to main and treat the resulting GitHub Actions run as the first genuine confirmation this repository has had of a green gate since 2026-07-14. Then proceed directly to PHASE-03 (security/hygiene) — it is small, independently scoped, and closes a credential-exposure item that has now gone unaddressed across five consecutive analysis sessions. PHASE-04 (tariff sign-flip) and PHASE-05 (Single Owner audit) are both live correctness questions and should follow once the security items are closed.
