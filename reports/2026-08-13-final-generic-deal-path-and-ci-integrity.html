01 / Executive Summary

Executive Summary

The problem

The offsite/DPPA pipeline could only analyze two named historical deals. A third deal — or any free-text Case id — hit a hard error even though the web UI promised a "generic runner" that did not exist. Separately, three things made the "green" CI badge misleading: a regulatory-watch invariant that would turn red on 2026-08-19 with no code change, a reproducible HTTP 500 on the second registered deal, and 26 tests that silently skipped in CI because they read git-ignored files the CI environment lacks.

What changed

Five phases shipped a generic fallback orchestrator (any unregistered case now returns a directional result), a versioned market-price data layer, honest extracted-inputs validation, a reproducible + scheduled CI with a skip budget, and declarative test markers replacing runtime skips. CI is green on both Python 3.10 and 3.12.

The result

The free-text Case id field is now honest, the offsite 500 is a clean 422, and the CI-enforced test surface is auditable: 655 passed, 0 skipped, 46 deselected, 3 xfailed on both legs (run 31677162076), verified with gh run list, not a local run.

The recommendation

Land the generic path as the registry default (done), flag every generic result directional so a bespoke model is never silently bypassed, and keep the market-price file behind the data manifest so a real published FMP/CFMP series can replace the proxy without a schema change.

02 / Background & Objective

Background & Objective

The repo's key function is techno-economic analysis of Vietnam clean-energy deals via a DealConfig descriptor routed through reopt_pysam_vn.analysis. After the eighth pass, the offsite registry had grown from one deal to two (DPPA_SAMSUNG_TTC, DPPA_CASE_1_NINHSIM), but registering historical deals one at a time would never make this a product. The ninth-pass brainstorm identified one named missing artifact — a versioned market-reference price series — as the last ingredient for a genuinely deal-generic DPPA path, plus three concrete defects in the CI signal.

The objective was to (1) make any DealConfig runnable through run_offsite_dppa; (2) fix the offsite consumer surfaces so the second registered deal is reachable end-to-end; (3) make CI self-firing, reproducible, and honest about skips; and (4) clear a dated regulatory-watch fuse before it fired on an unrelated push.

04 / Assumptions & Constraints

Assumptions & Constraints

Binding assumptions

  • No published hourly FMP/CFMP series is ingestible yet — the market-price file ships a documented PROXY (wholesale reference 671 VND/kWh, the Decree 243/2026 surplus rate) flagged proxy_cfmp_or_fmp.
  • A new deal's load must arrive as 8760 values; synthesizing a load from an annual total is explicitly out of scope (upstream callers use ingestion.synthesize).
  • The generic orchestrator never fetches over the network for generation — it prefers an explicit generation_kw, then a cached PVWatts resource, then a deterministic synthetic shape.
  • The exact composition of CI skips was read from the CI -rs output, not inferred locally (ASM-003).

Honesty constraints

  • Every generic result is flagged quality.basis == "directional" and echoes the resolved orchestrator name, so a fat-fingered case id is never silently given a bespoke-model answer.
  • Two regulatory-watch rows (tech_costs, emissions) could not be confirmed against a named primary source, so they were marked UNVERIFIED rather than bumping Last verified (ASM-001).
  • The extracted-inputs schema was corrected to describe the files that actually exist (DEC-005) — data files were not "fixed" to match a stale schema.
05 / Methodology

Methodology

The work proceeded in five phases with dependency-aware ordering: the deadline-critical CI phase and the two independent code phases ran first, the marker phase consumed the CI skip list, and the generic orchestrator landed last on top of the market-price layer and the error-handling refactor. Each phase was gated on its own exit criteria — ruff, mypy, the full portable suite, and gh run list --limit 3 showing green on both matrix legs. The market-reference refactor was value-preserving by construction (the shared helper reads per-deal data first and only falls back to the data layer), verified by recomputing the Case-2 proxy inline rather than trusting a stored golden. The skip-budget hook was validated against a deliberately skipped test to prove it fires, and against the xfail edge case to prove it does not fire spuriously.

06 / Phase-by-Phase Analysis

Phase-by-Phase Analysis

PHASE-01 — CI integrity

Reviewed the three expiring regulatory-watch rows (financials confirmed against CIT Law 67/2025/QH15; tech_costs + emissions marked UNVERIFIED). Added a weekly schedule: cron, -rs, and a skip budget (tests/conftest.py, REOPT_PYSAM_VN_MAX_SKIPS), and pinned the full dependency set in constraints-ci.txt (universal, 3.10-floor resolution) wired in via -c.

PHASE-02 — offsite consumer surfaces

Added OrchestratorInputError + signature-aware keyword forwarding in run_offsite_dppa; added --results/--scenario CLI flags and threaded both through the web API. A missing input is now a clean 422 (MISSING_INPUTS) with the run marked error, never a 500 with a run stranded in queued.

PHASE-03 — auditable test surface

Converted the environment-dependent skips to declarative requires_nrel_key / requires_pysam_resource / requires_artifacts markers, enabled --strict-markers, and added an in-process main(argv) CLI test so the public CLI is coverage-measured. The skip budget is now 0.

PHASE-04 — market-price data layer

Added data/vietnam/vn_market_prices_2026.json behind manifest.json (proxy, wholesale reference 671 VND/kWh) and a shared integration/market_reference.py. dppa_case_2 now delegates to it — value-preserving, verified by an inline recompute.

PHASE-05 — generic fallback orchestrator

Built analysis/orchestrators/generic_vn_dppa.py (load + generation + tariff + market reference + ContractParams.from_regime + settlement + 21-point strike sweep) and registered it as the registry fallback. Corrected the extracted-inputs schema (DEC-005) and wired validate_extracted_inputs at the offsite boundary.

07 / Findings & Recommendation

Findings & Recommendation

Finding 1 — the generic path was one missing data artifact, not a new engine. Every building block for a deal-generic DPPA run already existed and was tested (hourly settlement, contract terms from the policy data layer, strike sweep, PVWatts, load synthesis, 8760 TOU tariff). The only gap was a market-reference series, now shipped as an honest proxy behind the manifest. This turned "config-driven case runner" — a six-pass-old aspiration — into a half-built feature completed in one phase.

Finding 2 — the "green" signal hid three real defects. A dated invariant fuse, a reproducible 500 on a shipped deal, and 26 silently-skipped tests. The fixes were small but load-bearing: a scheduled workflow, a typed error mapped to 422, and declarative markers plus a skip budget. The skip budget itself had a subtle bug — a failing xfail test also carries report.skipped — that would have under-counted the true skip surface had it gone unnoticed.

Finding 3 — local and CI are genuinely different environments. The dev box has a warm artifacts/ tree, an NREL key, and a PVWatts resource cache; CI has none. Only the CI -rs output enumerated the true skip set, which was the git-ignored artifacts/ readers, not the NREL-key family a local simulation suggested.

Recommendation: keep the generic fallback as the registry default with directional flags, and treat the market-price file as a placeholder for a real published FMP/CFMP ingest. Do not register a third bespoke orchestrator — the free-text Case id would stay broken for everything not already in the repository.

09 / Risks / Open Questions

Risks / Open Questions

Risks

  • Generic results are directional, not bankable. A contract shape the generic path does not model (e.g. contracted-volume CfD with a floor) could produce plausible-but-wrong numbers; mitigated by the directional flag and a warning naming the registered cases.
  • The proxy market reference is a placeholder. It must not be mistaken for a published market price in client output.
  • A constraints file freezes security fixes out of the build until regenerated; the weekly cron + regeneration command in the header make refresh routine.

Open questions

  • Has the NREL key from commits 3911032/b14bc0b been rotated? (open ~40 days).
  • Should the regulatory-watch invariant block or warn? (adopted: block + scheduled run + 30-day warn tier).
  • Is a flagged proxy acceptable in client-facing output? (adopted: yes, flagged).
  • Should the generic orchestrator be the fallback or an explicit opt-in case id? (adopted: fallback, with the resolved orchestrator echoed in quality.orchestrator).
