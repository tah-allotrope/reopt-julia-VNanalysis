01 / Executive Summary

Executive Summary

The pipeline is green again, and the claims it masked are now true

Every push since 2026-07-26 had failed at the lint gate because the gate tool was unpinned and ruff expanded its default rule set between releases. Three consecutive red runs (30211921197, 30693998928, 30722078575) masked three structural gaps. This effort closed all four phases: CI is green on both matrix legs (verified with gh run list, run 31162599693), all 766 ruff violations are cleared against a pinned ruff 0.16.1, no document claims a guarantee the code does not enforce, the canonical VND/USD rate is now truly data-layer-driven, and run_offsite_dppa executes two registered deals.

02 / Background & Objective

Background & Objective

The repository is a techno-economic optimization toolkit for Vietnamese solar/wind/battery deals, with outputs that go to external counterparties. The plan (plans/2026-08-06-ci-gate-integrity-and-second-orchestrator-plan.md) was written because verification found the standing record wrong: activeContext.md said "CI status: Green on main" while the pipeline had been red on every push for eleven days and five commits. The red pipeline was not a code regression - it was a supply-chain-timing regression in an unpinned lint gate. But its redness also hid three genuine structural gaps:

  • Documentation advertised guarantees the code did not make. The webapp README and a module docstring claimed a bit-for-bit parity the tests deliberately do not assert; AGENTS.md carried a March-2026 test table and a repealed 20% export cap.
  • The FX resolver was threaded but short-circuited. 14 call sites pinned caller_value=26_400.0, which always wins, so editing the canonical data file moved 5 sites, not 19.
  • The public offsite API served exactly one deal. Any non-Samsung DealConfig.case raised "no offsite orchestrator registered".

The objective: restore CI integrity, finish the truth sweep, complete the FX derivation, and register a second offsite orchestrator - in that dependency order.

05 / Methodology

Methodology

Four phases, executed in strict dependency order, each with its own report and each verified end-to-end before the next began:

  • PHASE-01 (CI restoration) - baseline recorded (634 passed), gate tools pinned in a dev extra, CI pointed at it, 671 auto-fixable violations cleared with ruff check --fix (no unsafe fixes), 101 redundant # noqa: E402 comments removed, 72 manual violations triaged by category (BLE001/S110 narrowed per site; PySAM guards kept broad with documented noqa since PySAM raises a bare Exception), then the suite re-run byte-identical and both matrix legs verified green via gh run list.
  • PHASE-02 (truth sweep) - every surviving claim corrected to what the tests actually assert; the drift tripwire inverted to a measured, catalogued manifest; AGENTS.md sections rewritten; regulatory-watch dates + an overdue-row invariant added; three fully-merged branches deleted; the tests/cross_validate.py shim deleted and flat test shims banned.
  • PHASE-03 (FX derivation) - TDD: an authority test written first (failed on the 8 pinned sites), then the caller_value=26_400.0 argument removed from 8 general-purpose sites, the Samsung pin retained with a CON-001 comment, all 5 Saigon18 pins confirmed, suite re-run with zero numeric movement.
  • PHASE-04 (second orchestrator) - TDD: the case-1 test suite written first (failed with "no offsite orchestrator registered"), then the contract widened to (extracted, *, run_developer, results=None, scenario=None) with backward-compatible forwarding, the analysis/orchestrators/ package created, DPPA_CASE_1_NINHSIM registered, and a webapp acceptance test added proving POST /api/runs reaches done.

A post-hoc correction surfaced in CI: the drift-manifest test measured 15 diverging paths on the golden machine, but CI's Python 3.10 reproduces the golden nowhere near that (the whole settlement diverges), so that comparison now carries the golden_machine marker - the same exclusion the library-level parity test uses.

07 / Findings & Recommendation

Findings & Recommendation

Four findings drive the recommendation:

  • The gate was the bug, not the code. An unpinned linter that redefines its own defaults is not a control. Pinning every gate tool to an exact version and having CI install the pinned group removes the entire failure class.
  • "Green" must mean CI. Eleven days of unverified pushes came from reporting local runs as CI status. The repo's verification convention now mandates gh run list --limit 3 before any work is reported complete.
  • Unification is not derivation. FX was one value everywhere but one source nowhere. Making the data layer authoritative is provably value-preserving today precisely because values already agree - the window closes the moment any rate diverges again.
  • One deal is a front door with one key. A registry with two entries converts six sessions of "config-driven case runner" into a diff, and reveals which parts of the result vocabulary generalize (three of seven blocks came back empty for case 1 - an honest signal, not a bug).

Recommendation: adopt the pinned gate + CI-verification convention as standing policy (now in AGENTS.md and lessons.md), keep the data layer authoritative for FX, and treat DPPA_CASE_1_NINHSIM as the template for a third registration rather than a one-off.
