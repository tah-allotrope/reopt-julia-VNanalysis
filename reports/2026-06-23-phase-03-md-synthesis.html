03 / Math / Algorithm Used

Math / Algorithm Used

The synthesis is formatting logic, not math. Three pieces of structure matter:

  • Verdict icon mapping. One-line dict {ok: "✅", warn: "⚠️", info: "ℹ️", bad: "❌", skip: "➖", err: "💥"}. The same icons appear in the per-slide notes (Phase 4) so colleagues see one consistent visual language across the markdown, the deck notes, and the final HTML report.
  • Value formatting. Floats < 0.01 render as scientific (so 5e-3 doesn't show as 0.005000); floats ≥ 0.01 use thousands separator; lists > 8 items collapse to […N items…] so a 6,000,000 kWh list of 6 zeros doesn't blow up the table. This is purely cosmetic but it keeps the table scannable.
  • Hand-curated structural reconciliations. Six items (A06/A07 kpp collapse, B11/B13 null IRR, B12/B14 negative DSCR, A12 FMP cited mismatch, A02 TOU peak multiplier gap, A04 service-fee basis). These are the items the orchestrator marks as ❌/ℹ️/⚠️ but where the gap is explainable — the markdown callout gives colleagues the explanation, not just the verdict.

06 / Limitations / Second-Best Alternative

Limitations / Second-Best Alternative

  • Structural reconciliations are hand-curated, not derived. Six items live in the script. If the JSON's verdict distribution changes (say, a new ❌ appears), the markdown will show the new row but won't auto-call out a structural reason. The alternative — auto-detect "kpp-related" or "PySAM-null-IRR" tags from the registry — would require extending the registry. Acceptable trade-off for now: the registry is the single source of truth, and structural callouts are review-quality commentary that should be human-reviewed anyway.
  • One table per bucket. Slides 12, 13, 17, 24 each appear in 1+ tables (B/C). A flat single table by slide would let colleagues scan top-to-bottom, but the per-bucket split keeps the methodology visible (assumption vs finding vs insight). The tradeoff is "readability by method" vs "readability by slide" — Phase 4's note injector does the per-slide read for the deck itself.
  • No chart in the markdown. The report skill is HTML-only. The markdown is plain text — the verdict distribution lives in a single table. That's the right place for a one-screen colleague-friendly artifact; the chart is in the HTML report.
