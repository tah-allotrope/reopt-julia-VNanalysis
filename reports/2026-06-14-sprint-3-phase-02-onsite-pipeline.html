03 / Math / Algorithm Used

Math / Algorithm Used

Dispatch coverage, mirroring the bespoke ninhsim logic exactly:

  • delivered = Σ max(0, PV→load + Wind→load + storage→load) over 8760h (zero-padded)
  • exported = Σ max(0, PV→grid + Wind→grid); grid = Σ max(0, utility→load)
  • achieved_fraction = delivered / total_load, with total_load = Σ max(0, loads_kw)

On the shared fixture: delivered 120, exported 10, grid 50, load 170 → achieved 0.7059 — identical to calculate_ninhsim_coverage_summary.

06 / Limitations / Second-Best Alternative

Limitations / Second-Best Alternative

  • Limitation: the real Julia solve path (solve_fn + build_onsite_scenario) is wired but not exercised in CI — only the deterministic post-processing is parity-tested. Full-solve parity stays behind a manual/Layer-4 run.
  • Limitation: the coverage logic is currently duplicated in onsite.py and the ninhsim module; the parity test guards drift, and PHASE-05 will point the ninhsim wrapper at onsite.py to collapse it.
  • Second-best alternative: import the ninhsim helpers into analysis/. Rejected — wrong dependency direction (case modules should depend on analysis, not vice-versa).
