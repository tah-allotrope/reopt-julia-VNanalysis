03 / Math / Algorithm Used

Math / Algorithm Used

  • Load factor: average_demand / peak_demand. Saigon18 = 0.695 (typical continuous industrial).
  • TOU bucketing: Each of 8760 hours is classified as peak/offpeak/standard based on hour-of-day and day-of-week. Decision 963 maps: peak = hours 17-22 Mon-Sat, offpeak = hours 0-5 all days, standard = remainder.
  • Weekend/weekday ratio: weekend_avg_kw / weekday_avg_kw. Saigon18 = 1.015 (nearly flat → continuous operation).
  • Night/day ratio: nighttime_avg_kw / daytime_avg_kw. Saigon18 = 0.959 (near-unity confirms 24/7 operation).
  • Peak concentration: mean(9am-5pm weekday kW) / overall_mean_kw. Measures how much load concentrates in business hours.
  • Archetype decision tree: continuous_process if nd > 0.7 AND ww > 0.7; single_shift if ww < 0.3 AND nd < 0.4; two_shift if ww < 0.6 AND nd > 0.4; commercial variants by peak_concentration thresholds; load_factor tiebreaker for ambiguous cases.
  • Confidence scoring: High = clearly within thresholds (e.g., nd > 0.85 and ww > 0.85 for continuous). Medium = within primary thresholds but not deep. Low = fallback classification.

06 / Limitations / Second-Best Alternative

Limitations / Second-Best Alternative

  • Hour-boundary approximation: Decision 963 peak starts at 17:30 but the module maps to hour 17 (17:00-17:59). This causes ~2.8% overcount of peak energy. Sub-hourly TOU bucketing would fix this but adds complexity.
  • No public holidays: Sunday schedule is used for Sundays only; Vietnamese public holidays are not explicitly mapped. This slightly underestimates offpeak consumption for factories that shut down on holidays.
  • Archetype thresholds are heuristic: Not trained on labeled data. Edge cases (e.g., a mall with extended hours) may misclassify. The confidence field flags uncertainty, and downstream workflows can override.
  • Saigon18 and ninhsim have identical load profiles: This is expected — ninhsim's NinhsimSample.csv is the same load data as saigon18, just in a different format.
