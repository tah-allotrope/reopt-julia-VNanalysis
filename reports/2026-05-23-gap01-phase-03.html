03 / Math / Algorithm Used

Math / Algorithm Used

  • Sub-hourly resampling: Simple averaging of N intervals per hour. 15-min: hourly[h] = mean(values[4h:4h+4]). 30-min: hourly[h] = mean(values[2h:2h+2]). Preserves total energy (sum of hourly averages equals sum of sub-hourly averages).
  • Monthly-to-8760 offline scaling: Reference shape S[h] is a normalized 8760 vector where ΣS = 1. For each month m, compute scale_m = monthly_kwh[m] / (sum(S[month_m_hours]) * annual_kwh). Each hour's load = S[h] * annual_kwh * scale_m. This preserves monthly energy targets while following the reference shape's diurnal pattern.
  • API synthesis: REopt simulated_load endpoint generates 8760 from DOE reference building type and annual kWh. Used as primary when API key is available; falls back to offline on failure.

06 / Limitations / Second-Best Alternative

Limitations / Second-Best Alternative

  • Single reference shape: Only industrial_south.json (from saigon18) is available. For non-industrial or non-south factories, the diurnal pattern may not be representative. Plan noted creating 2-3 additional shapes if time permits.
  • REopt API may not have representative Vietnamese load shapes: The doe_reference_name values are US building types. Offline fallback using the saigon18 industrial shape is more appropriate for Vietnam-specific profiles.
  • Monthly scaling preserves monthly totals but not sub-monthly patterns: If monthly consumption is highly variable (e.g., Tet shutdown), the reference shape won't capture that.
  • No leap year handling: All years are treated as 365 days / 8760 hours.
