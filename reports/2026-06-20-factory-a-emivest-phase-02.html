03 / Math / Algorithm

Math / Algorithm Used

Formula / MethodValue / Notes
ESCO PPA price esco_usd = 0.90 × Σ(load[h] × rate_vnd[h]) / Σ(load[h]) / 26400 — load-weighted average EVN TOU rate discounted 10%, converted USD at 26,400 VND/USD.
Clean self-supply % clean_pct = annual_matched_load_kwh / sum(loads_kw) × 100. annual_matched_load_kwh from PySAM energy summary = kWh served directly by PV+BESS without grid.
Approx annual savings savings = matched_kwh × (evn_avg_usd − esco_usd) = energy displaced × rate spread. Proxy for year-1 bill savings; Single Owner doesn't directly export this metric.
Case 3 demand charge savings Δ_peak_m = max_load_m − max_grid_m; annual_DC_savings = Σ Δ_peak_m × rate_usd/kW/month. Applied at slide rate 209,459 VND/kW/month and repo rate 235,414 VND/kW/month as sensitivity.
Case 4 BESS sentinel Solar-only case requires battery_power_kw > 0 for PySAM validation. Nominal 1 kW / 1 kWh injected; contribution to results negligible (< 0.01% of 9,750 MWh load).
Financial structure 70% debt, 8.5% VND interest, 10-yr tenor, 10% owner discount rate, 25-yr analysis horizon. US MACRS depreciation (BIAS-03 — noted, not resolved in this run).

06 / Limitations

Limitations / Second-Best Alternative

Remaining BIAS flags

  • BIAS-02 (hybrid IRR): PySAM Single Owner computes equity IRR not the blended project-level IRR that Cong's model may use. ESCO economics typically quoted as equity IRR — this is likely correctly aligned, but the comparison should be flagged.
  • BIAS-03 (US MACRS depreciation): PySAM defaults to US tax code. Vietnam ESCO projects use straight-line VND depreciation over 10–15 years. Tax shield differs materially. NPV figures are therefore biased against VN projects.
  • BIAS-04 (savings definition): Year-1 savings is approximated as matched_kwh × rate_spread, not a direct bill calculation. PySAM Single Owner does not output bill savings natively in this configuration.
  • Day/night gap: Real load is 70% day vs slide-implied ~54% day. Even with real data, CSS will be higher than the slide if Cong used a flatter load profile. PHASE-03 comparison will quantify the remaining gap.

Alternative path not taken

  • ALT-001 was chosen: Slide-fixed PV/BESS sizing rather than REopt optimizer. This eliminates the solver dependency and guarantees the same hardware config as Cong's model, making CSS and IRR directly comparable.
  • ALT-002 (30-min resolution): Emivest 30-min profile exists in repo. Resampling to hourly averages would smooth the peak kW (reduce from 2,443 to potentially 2,280–2,350 kW), reducing apparent BESS utilization. Not chosen — consistent with prior hourly model.
  • ALT-003 (manual demand calculation): Demand charge post-processing is an approximation using hourly average PV dispatch. A proper implementation would use the full hourly dispatch array from PySAM — flagged as future improvement if Case 3 comparison diverges.
