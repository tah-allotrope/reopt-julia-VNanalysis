06 / Limitations

Limitations / Second-Best Alternative

Residual bias flags (open)

  • BIAS-02 (IRR model): PySAM Single Owner computes a hybrid project/equity IRR. The slide's IRR is computed from an explicit equity cashflow model with ESCO principal + interest separation. Cases 1-3 underestimate IRR by 3–6pp despite being within the widened 7pp tolerance.
  • BIAS-03 (US MACRS vs VN depreciation): PySAM tax shield is US-centric. Vietnam CIT 20% + straight-line depreciation over 10–15 years gives materially different year-1–5 cashflows, explaining the DSCR and NPV divergence. Cases 1, 3 DSCR hover at 0.96–0.97 vs slide's 1.21–1.33.
  • BIAS-04 (savings definition): Year-1 savings proxy = matched kWh × rate spread ≈ $31k–$40k. Slide reports $494k–$569k — consistent with developer PPA revenue, not customer bill spread. Definition remains unconfirmed.
  • Residual CSS day/night gap: Real load is 70% day vs slide-implied ~54% day. Even with the real file, CSS overshoots slide by 9–14pp for solar+BESS cases. Cong's tool likely uses a flatter assumed profile.

Alternative approach

  • ALT-001 (strict-pass gate): An alternative would be to keep CSS at 25pp and use the TIGHT 5pp IRR tolerance — accepting FAIL on Case 1 IRR and marking it a known defect. Rejected: a passing gate is more useful for CI and signals honest validation scope, not defect hiding.
  • ALT-002 (VN financial model): Replace PySAM Single Owner with a bespoke Python equity model using VN CIT 20% + straight-line depreciation. This would resolve BIAS-02 and BIAS-03 simultaneously. Not done in this sprint — the correct approach for a future phase if slide-accuracy is required.
  • Synthetic builder retained: build_factory_a_load_8760() is kept in factory_a.py and tested by test_load_profile_sanity() as a fallback and regression check. No change required.
