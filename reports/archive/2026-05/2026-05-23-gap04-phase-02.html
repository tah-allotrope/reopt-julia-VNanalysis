03 / Math / Algorithm Used

Math / Algorithm Used

  • Strike sweep: Uses dataclasses.replace() to create a new ContractParams with each candidate strike while preserving all other parameters from the base preset. Each iteration runs a full 8760-hour settlement.
  • Benchmark savings: savings = ∑(loadh × tariffh) − buyer_cost_vnd. Positive savings means the DPPA is cheaper than EVN-only.
  • Monotonicity property: For virtual CfD with constant FMP, higher strike → higher buyer CfD payment → higher buyer cost. For private wire, higher strike → higher developer revenue (directly proportional).
  • Preset sourcing: Decree 57 private-wire preset uses south ground no-storage ceiling (1,012 VND/kWh), 20% export cap, 671 VND/kWh surplus rate. Virtual CfD presets use Case 2’s proven adder/KPP values.

06 / Limitations

Limitations / Second-Best Alternative

  • Preset strike prices are placeholder anchors: The 1,012 VND/kWh for private wire is the Decree 57 ceiling. The 1,800 VND/kWh for virtual CfD is a representative value from Case 2. Actual strike should be computed from the site’s weighted EVN tariff using the strike sweep.
  • No developer-side IRR integration yet: The sweep returns developer revenue but does not run PySAM Single Owner to check IRR feasibility. This is a PHASE-03 concern (regression validation) and a future Bankability Studio feature.
  • Sweep is serial: Each strike point runs a full 8760-hour settlement. For large sweep ranges this is fine (sub-second per point) but could be parallelized if needed.
  • Alternative considered: Using percentage-of-EVN anchoring (e.g., 85%, 90%, 95%) instead of absolute VND/kWh strikes. Not chosen because the absolute-strike API is more general and the calling code can compute percentage anchors trivially.
