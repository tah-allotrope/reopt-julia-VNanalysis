06 / Limitations / Second-Best Alternative

Limitations / Second-Best Alternative

  • Delivery factor gap: The original dppa_settlement.py uses a delivery_factor (0.98) that the generalized engine does not natively support. The regression tests work around this by pre-scaling the generation series. A future enhancement should add delivery_factor as a first-class ContractParams field.
  • Zero tariff/FMP for private-wire: The saigon18 regression passes zero arrays for tariff and FMP since private-wire settlement only uses the strike rate. This is correct for the current case but limits the engine's ability to model hybrid scenarios where private-wire energy is partially supplemented by grid purchases at TOU rates.
  • Single-year only: Regression validates year-1 hourly settlement. Multi-year escalation, degradation, and discounting are outside the generalized engine's scope (handled by downstream analysis layers).
  • Second-best alternative: Instead of regression testing, the engine could be validated against hand-computed synthetic inputs. This would be simpler but would not prove compatibility with existing case-study artifacts that real stakeholders depend on.
07 / Errors / Warnings / Flags

Errors / Warnings / Flags Encountered

  • No errors: All 13 tests passed on first run. No test failures, no import errors, no missing artifacts.
  • Flag — delivery factor workaround: The saigon18 regression requires pre-scaling generation by the delivery factor (0.98) because the generalized engine does not have this parameter. This is documented in the test file comments and should be addressed in a future enhancement.
