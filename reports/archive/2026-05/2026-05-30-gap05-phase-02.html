Math / Algorithm Used

Solar avoided costΣ min(pv[h], load[h]) · rate[h]Per regime; behind-the-meter avoided energy capped at load.

Because Decision 963 and Decision 14 share the same rate multipliers (only the windows differ), the peak/off-peak spread is identical — so the arbitrage difference is driven purely by the cycle count (1 vs 2), landing the 963/14 ratio at ≈ 0.50.

04 / Tools / Formulas / Methods

Tools / Formulas / Methods

  • Reuse: PHASE-01 engine + GAP-01 ingest_factory_load() (CSV/XLSX/JSON) for the CLI's --factory / --solar-profile.
  • Window detection: peak hours-of-day = hours that ever carry the max rate; contiguous runs = cycles (wrap-around counts once).
  • Labelling: BESS basis explicitly tagged theoretical_maximum_no_efficiency_losses (RISK-02-01).
  • CLI: argparse; --bess-capacity defaults to --bess-power × 4h; writes indented JSON, creating parent dirs.
  • Verification: MANUAL-001 run on ninhsim produced a valid artifact (delta -9.81 B VND, cycles 1/2).
05 / Results & Visualizations

Results & Visualizations

Example: saigon18 load, a 1 MW daytime PV profile (07:00–16:59), and a 1 MW / 4 MWh battery. Decision 963 strips the morning peak premium, so the same solar earns ~14% less avoided cost, and the battery loses its second daily arbitrage cycle — roughly halving theoretical arbitrage.

06 / Limitations / Second-Best Alternative

Limitations / Second-Best Alternative

  • BESS arbitrage is a ceiling. Perfect foresight, no round-trip efficiency, no degradation, no concurrent demand-charge management — explicitly labelled as theoretical maximum.
  • Solar value is avoided-cost only. No export revenue, no curtailment, no co-optimization with the battery.
  • Per-cycle energy heuristic. A 2-hour nominal block caps energy by power; real dispatch depends on window length and SoC.
  • Second-best alternative: a full REopt co-optimization of PV+BESS per regime. Rejected for the same reason as PHASE-01 — solve latency kills the instant-toggle UX (ALT-001).
