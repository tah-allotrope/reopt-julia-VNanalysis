01 / Executive Summary

Executive Summary

What was wrong

Three deck .pptx files and two root screenshots stayed tracked in git despite .gitignore entries meant to exclude them — two of those ignore lines used unescaped bracket-glob syntax that silently never matched the filenames they named. requirements.txt duplicated pyproject.toml's dependency list. A historically leaked NREL API key (recoverable from two old commits) had no rotation record anywhere in the repo's docs, despite being flagged across six consecutive analysis sessions. Separately, and more materially: the PySAM "Single Owner" finance wrapper never touched twelve SAM cost-model fields that default to ~100 MW-reference-plant values — led by a flat $2,866,500 construction-financing charge — and every historical result this repository has produced, including the bit-exact Samsung/TTC golden fixture and the CEBA/DPPA July 2026 client-deck verification pipeline, was generated with those defaults silently in place.

What was done

Phase 1 untracked the three deck binaries (kept on disk), fixed both broken .gitignore patterns, removed requirements.txt in favor of a single dependency source, and wrote down the key-rotation requirement in README.md and activeContext.md with both source commit hashes. Phase 2 added an opt-in, default-False zero_reference_plant_defaults flag to the Single Owner wrapper — legacy behavior is byte-identical when it is off — then used it to run a quantified before/after comparison and write a full caller audit (reports/2026-07-24-single-owner-defaults-audit.md) naming every file in this repository that calls the finance model, whether it feeds a real deliverable, and what the un-zeroed defaults are worth in dollars and IRR points on two representative projects.

02 / Background & Objective

Background & Objective

reopt-pysam-vn models solar/wind/storage/DPPA project economics for Vietnam using NREL REopt.jl plus PySAM, and its outputs feed real client deliverables — most notably the Samsung/TTC combined decision package and the CEBA/DPPA July 2026 case-study deck. Six consecutive unattended analysis sessions (2026-07-11 through 2026-07-22) converged on the same conclusion: the repository's bottleneck was not a shortage of ideas but an execution gap on already-diagnosed, low-risk items — most visibly, a security/hygiene cleanup that kept getting re-flagged as "next" without ever landing. The most recent of those sessions (2026-07-22) finally broke that pattern: CI truth work landed on main and the gate went green for the first time in ten days. This report's plan (plans/2026-07-24-post-ci-hygiene-finance-audit-plan.md) was written immediately after, specifically to close the one item that had now survived six sessions of being "next" (the security/hygiene backlog) and to resolve a newly-traced, higher-stakes finding: that a known PySAM modeling gap sat directly on the call path to the two client-facing deliverable pipelines this business actually relies on.

04 / Assumptions & Constraints

Assumptions & Constraints

Assumptions carried into implementation

  • The three tracked deck .pptx filenames and the two root PNGs matched exactly what the plan expected — verified live via git ls-files before untracking, not assumed from the plan text
  • The installed .venv PySAM version (nrel-pysam==7.1.0) matched the plan's recorded field defaults — re-verified live immediately before writing any test expectation; all twelve values were identical to the plan's recorded figures, so no test expectation needed adjusting

  • The audit report draws a firm line between "this cost assumption exists and is material" (established as fact) and "this specific delivered number is wrong" (explicitly not concluded) — the decision on whether any client-facing number needs re-review is left to the people who own those relationships
05 / Methodology

Methodology

Every claim in this report was checked against live tool output in this session, not inherited from the plan's own text. Before untracking any file, git ls-files and git check-ignore -v confirmed the exact tracked paths and that the corrected .gitignore patterns actually matched them. Before writing any PySAM test expectation, the twelve SAM FinancialParameters field values were read live off an installed nrel-pysam model instance rather than trusting the plan's recorded figures — they matched exactly, confirming no drift since the plan was written. The clean-slate flag was built test-first: seven tests were written and confirmed to fail for the expected reason (a missing dataclass field and a missing function) before any implementation code was touched, and a genuine PySAM access-violation crash surfaced during that RED phase — from an incomplete model-build helper in the test file, not from the production code — and was fixed by mirroring the exact Grid/Utilityrate5/Singleowner model chain the production function already uses. The audit's caller list was produced by re-running the repository-wide git grep live rather than reusing a cached list from an earlier brainstorm pass, and two grep hits that turned out to be false positives (a package re-export and an unrelated, similarly-named dataclass) were read in full and excluded from the audit's conclusions rather than counted uncritically.

07 / Findings & Recommendation

Findings & Recommendation

Finding 1 — the security/hygiene backlog is now actually closed, not just re-documented. Every one of Phase 1's five test specs holds: no .pptx or root PNG remains tracked, both .gitignore patterns now match the files they name, and the key-rotation requirement is written down with both source commit hashes rather than existing only in prior brainstorm documents.

Finding 2 — every historical Single Owner result in this repository, including the flagship Samsung/TTC golden and the CEBA deck-verification pipeline, was generated with twelve un-audited SAM cost defaults in place. This was traced by direct source reading, not inferred: dppa_samsung_ttc.py:771 calls run_single_owner_model in the Samsung/TTC strike-sweep, and five files under scripts/python/integration/ceba_deck/ — the exact pipeline that checked and annotated the CEBA/DPPA July 2026 client deck — do the same.

Finding 3 — the effect is not a rounding-level curiosity; it is material at every scale tested. On a real, artifact-backed ~100 MW project, zeroing the twelve fields shifted project NPV by roughly $13.8M and IRR by over two full percentage points. On a small, synthetic 1 MW project representative of typical Vietnam C&I scale, the same change moved NPV by about $2.4M and flipped IRR from a null/negative signal to a real, positive 7.95% — the difference between a project reading as economically non-viable and clearly viable, from one static cost assumption alone.

Recommendation. Do not flip the clean-slate flag's default anywhere and do not touch the Samsung/TTC golden — both remain explicit non-goals this session honored. Instead, route reports/2026-07-24-single-owner-defaults-audit.md to whoever owns the Samsung/TTC and CEBA client relationships so they can make an informed call on whether any already-delivered number needs a second look. Separately, proceed to PHASE-03 and PHASE-04 of the source plan — both are small, independent, and were correctly deferred rather than rushed in this session.
