03 / Math / Algorithm Used

Math / Algorithm Used

Phase 1 is data modeling, not numeric computation. The structural choices that matter for downstream phases:

  • Two-bucket enumeration. Every slide claim lands in exactly one of A (assumption: data file value vs deck value), B (finding: deck-stated number reproducible by the engine), or C (insight: qualitative statement the engine demonstrates). KnownGap rows cover the fourth category — relevant but unmodeled.
  • Per-check provenance. Each Check pins slide, deck_value, deck_unit, deck_citation (when present), repo_fn (dotted Python path), and repo_source_ref (file:line) so the orchestrator never has to second-guess where a value came from.
  • Per-check assumptions. Where the deck is silent (e.g., whether to use the engine's blended kpp_factor or honor the deck's split k=1.026 × Kpp=1.008), assumptions lists the resolved choice so the verdict block in the deck note can show "assumed: …" alongside the result.
  • Citation-preserving comparison (DEC-008). A slide that cites a value which diverges from repo data is never auto-❌. The orchestrator will classify those as ⚠️ reconcile with both bases shown; the registry's deck_citation field is the input to that classifier.

06 / Limitations / Second-Best Alternative

Limitations / Second-Best Alternative

  • Static, hand-curated registry. A new deck version (slides added or figures changed) requires manual re-mapping. The alternative — auto-extract every numeric in the deck and call the engine for each — is rejected: it cannot read context (which 2,204 is the deck's claim vs which is a citation?). Keeping the registry human-authored keeps the citation-preserving verdict classifier honest.
  • One bucket per claim. A claim like "DSCR < 1.20x" lives in B (numeric) for Case 5 and C (insight) for the "oversized BESS sinks the deal" generalization. The registry is opinionated about primary placement; the orchestrator can classify either way but the report will use the registry's bucket.
  • No slide-text auto-pin. Check.claim is a paraphrase, not a direct quote. Acceptable for the report tables; Phase 4's note injector uses slide + repo_fn to locate the right slide, not the text. If we ever need strict quote-matching, a future phase can extend Check with a text_anchor field.

The orchestrator's ±1% rule is the safety net.
  • No known structural blockers for Phase 2. The registry covers every claim the brainstorm enumerated (20+ checks across A/B/C + 3 known gaps, well past the plan's exit criterion of ≥20).
