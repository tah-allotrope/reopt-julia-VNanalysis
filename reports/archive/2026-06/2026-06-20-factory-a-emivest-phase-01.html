03 / Math / Algorithm

Math / Algorithm Used

StepFormula / MethodApplied to
Outlier detection value > 5,000 kW → mark None. Threshold chosen from bimodal distribution: clean readings cluster 0–2,500 kW; erroneous readings cluster 37,000–42,000 kW. Gap between 2,500 and 5,000 kW is empty. 24 rows removed
Missing value detection Blank string, dash "-", or non-parseable Load_kW → mark None. 347 rows removed
Linear interpolation loads[i] = raw[prev] + t × (raw[next] − raw[prev]) where t = (i − prev) / (next − prev). Boundary case: use nearest valid neighbour. 371 gap-filled indices
Annual scaling factor = 9,750,000 / sum(cleaned_loads) ≈ 1.047. All 8,760 values multiplied by factor. Preserves shape; adjusts magnitude to match slide stated consumption. Full array, post-cleaning
Day/night split day = Σ loads[h] where h%24 ∈ [6,22); night = total − day. Split: 69.6% day / 30.4% night (vs synthetic 78%/22%). Diagnostic metric
04 / Tools / Methods

Tools / Formulas / Methods

Implementation

  • load_emivest_8760(path, scale_to_kwh, outlier_threshold_kw) — pure Python, no external dependencies beyond stdlib csv.
  • Opens with encoding="utf-8-sig" to handle Windows BOM in CSV.
  • _REPO_ROOT = Path(__file__).parents[4] — makes path resolution portable; no hardcoded absolute paths in committed code.
  • Synthetic builder build_factory_a_load_8760() retained as documented fallback.
  • Both functions share _validate_load() — length assert + stats dict.

Decision rationale

  • Scale to 9,750 MWh (Q2): Natural cleaned total is ~9,315 MWh — 4.5% below slide. Cong likely normalised before running the model. Scaling preserves load shape while matching the stated annual figure.
  • Track in git (Q1): 263 KB CSV — well within git limits. Reproducibility requires the source file; external-only reference would break for any other reviewer.
  • Outlier threshold 5,000 kW: The bimodal gap between valid readings (max ≈ 2,428 kW) and erroneous readings (min ≈ 37,000 kW) is wide. Any threshold between 3,000 and 10,000 kW gives identical results.

06 / Limitations

Limitations / Second-Best Alternative

Remaining gaps

  • Day/night still 70/30 vs slide's ~54/46. The real meter data has a stronger daytime bias than the slide implies. Clean self-supply will improve vs the synthetic run but may not fully converge to slide figures — the gap likely reflects a different model assumption in Cong's tool (e.g. hourly vs 30-min demand resolution, or a different base year).
  • BIAS-05 (natural total vs slide): Raw cleaned total was 9,315 MWh (4.5% below slide). Scaling to 9,750 MWh inflates all values by factor 1.047. This is the correct approach per Q2, but a reviewer should know the raw data undershoots the stated annual consumption.
  • BIAS-02, BIAS-03, BIAS-04 remain: IRR (hybrid PySAM model), depreciation (US MACRS vs VN straight-line), and savings metric definition are unchanged.

Alternative not chosen

  • ALT-001 (30-min Emivest file): Emivest_load_profile_30min_annual.csv.csv has 17,519 rows at 30-min resolution. Resampling to 1-hr by averaging pairs would give a cleaner profile but identical information content. Not chosen — same underlying data, more processing complexity, PySAM ingests 1-hr natively.
  • ALT-002 (WH01 + WH02 separately): The Load Profile/ folder has raw EVN meter exports for two Emivest warehouses (WH01 and WH02). The pre-processed 1hr.csv is already their combined total. Reaggregating from scratch was not required.
  • ALT-003 (keep synthetic): The prior report documented synthetic as fallback. Retained in module; not used for results.
