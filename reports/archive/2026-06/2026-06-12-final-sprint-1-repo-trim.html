01 / Executive Summary

Executive Summary

What was done

The repository carried a working analysis engine buried under regenerable output. Sprint 1 removed that weight in four committed, individually-verified phases: preserve golden references, untrack generated artifacts, delete dead/foreign directories, then verify and document. Every phase was committed and pushed to main with its own HTML report.

Why it matters

The de-bloat is purely mechanical and reversible — nothing in the REopt (onsite/BTM optimization) or PySAM (offsite/DPPA finance) code changed. The payoff is a tree where the ~370 tracked files are actual source, data, tests, and deliverables, so the upcoming structural work (Sprints 2–3) lands on a clean surface.

Headline result

Tracked files fell 635 → 371 (−42%). The 62 MB of regenerable artifacts/ still sit on disk (git-ignored) and a report script was confirmed to still write there. Three golden runs are frozen in examples/.

The one catch

Deleting archive/ broke a test that loaded a function from it via path segments — invisible to the initial grep. It was caught in the verification phase, root-caused, and fixed by relocating the function to canonical source. No broken test shipped.

02 / Background & Objective

Background & Objective

A gap analysis on 2026-06-12 found the repo's key function — using NREL REopt and PySAM to analyze future onsite and offsite/DPPA clean-energy projects in Vietnam — healthy but obscured. Of 635 tracked files, well over half were regenerable output or cruft: 62 MB of artifacts/, 76 generated HTML reports, decks, a 19 MB dead Google-Colab archive/, and foreign tooling. The analysis sequenced the cleanup into three sprints; this report covers Sprint 1 — the mechanical de-bloat (gaps GAP-02 generated artifacts, GAP-04 dead/foreign dirs, GAP-09 stray files).

The objective was deliberately narrow: shrink the tracked tree and remove noise without changing a single line of pipeline behavior. Untrack, don't delete; preserve golden references; prove the pipeline still runs.

Constraints

05 / Methodology

Methodology

Each phase followed the same loop: implement → generate a phase HTML report → commit → push to main. Removals favored the least destructive operation that achieved the goal — git rm --cached (untrack, keep on disk) over git rm (delete) wherever any script or future run might still need the file. A safety grep preceded every deletion, and the final phase ran the test suite as the gate, treating a "pure deletion" as unproven until tests passed.

07 / Findings & Recommendation

Findings & Recommendation

Finding 1 — The bloat was real and removable without risk. 264 net tracked files were regenerable output or dead material. Untracking (not deleting) removed them from git while a smoke run proved scripts still write to artifacts/ on disk.

Finding 2 — "Dead" directories can hide live dependencies. archive/ looked dead, but a test imported a sanitizer from it via path segments (REPO_ROOT / "archive" / …) that a grep "archive/" never matched. The fix relocated redact_sensitive_fields into src/python/reopt_pysam_vn/reopt/sanitize.py — a better home than the archive ever was.

Recommendation. Proceed to Sprint 2 (remove the two shadow shim layers, relocate heavy binaries) — it is the same pattern proven here: relocate tested code to canonical source, then delete. The history-rewrite question (to actually shrink clone size) can stay deferred; untracking already stopped the growth.

Glossary

  • Untrack vs delete: git rm --cached removes a file from git's index but leaves it on disk; git rm removes both.
  • Onsite: behind-the-meter REopt PV+BESS optimization vs EVN time-of-use tariff.
  • Offsite/DPPA: Direct Power Purchase Agreement — PySAM developer finance + settlement.
  • Golden run: a frozen reference output kept for documentation/regression.

Lesson recorded

Before deleting a directory, grep the bare name (archive), not the path form (archive/) — code builds paths from segments that the slashed form never matches. A directory with a live test dependency is not dead: relocate the depended-on code to canonical src/. Always run the suite in the verify phase. (See lessons.md, 2026-06-12.)
