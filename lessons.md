# Lessons

- 2026-08-13: A "skip budget" conftest that counts `report.skipped` will silently over-count, because a failing `@pytest.mark.xfail(strict=False)` test ALSO carries `report.skipped=True` (its expected failure is reported through the skip channel). The distinguishing field is `report.wasxfail` — set only for xfail outcomes. Rule: count a skip as `report.skipped and not report.wasxfail`, or the budget diverges from pytest's own "N skipped" summary. Also: the composition of CI skips must be read from the CI `-rs` output, not inferred locally — the "26 skips" were git-ignored `artifacts/` readers (factory-a PySAM results, settlement-regression artifacts, e2e example results), not the NREL-key/PySAM-resource family a local simulation (removing only the key + resource cache) suggested; the local box has `artifacts/` warm so those guards never fire there.
- 2026-08-13: When writing a file with a PowerShell here-string, a **double-quoted** here-string (`@"…"@`) treats backticks as escape chars, so a header containing `` `foo` `` gets mangled (`` `r `` is a CR; backtick-newline is a line continuation). Use a **single-quoted** here-string (`@'…'@`) or the file-write tool, and verify `pip` can parse the result. A corrupted line in `constraints-ci.txt` failed CI at install ("Invalid requirement"), which was only visible because the run aborted in 14 s — far under the ~1m30s test time.
- 2026-08-06: Local green and CI green are different claims, and "CI status: Green" written from memory is how a red pipeline went unnoticed for eleven days. An unpinned gate tool that redefines its own defaults between releases (ruff's expanded default rule set) breaks every push without touching a line of code. Rules: (1) pin every gate tool to an exact version in a `dev` optional-dependency group and have CI install that group, so a third-party release cannot break the build; (2) verify work complete with `gh run list --limit 3` — the authoritative green signal — not a local run; (3) check the CI job duration: a run that finishes well under the historical test time has not reached the test step (the three red runs aborted at lint in 44–48 s vs ~1m30s green).
- 2026-04-01: When ranking case-study offtakers for this repository, treat physical load matching and contract-structure risk as separate screens unless the user explicitly asks to combine them.
- 2026-04-02: When generating HTML reports with Chart.js for this repository, always wrap canvases in explicit-height containers and verify browser rendering over HTTP so auto-sized canvases do not explode the page height.
- 2026-06-14: When generalizing bespoke logic, run an EXPLORATORY diff against the golden BEFORE writing parity assertions — calibrate the test to reality, don't guess the tolerance. Sprint 3's `run_offsite_dppa` reproduced the Samsung golden bit-for-bit (136 numeric fields, max rel diff 0.0) because it routes to the same builder on the same deterministic PVWatts resource; the ≤0.5% bar was never exercised. Also: in a recursive numeric comparator, guard `bool` BEFORE `int` (Python's `bool` ⊂ `int`) or decision flags get compared numerically.
- 2026-06-14: Watch for circular delegation when "wrapping." DEC-003 said case modules should wrap the new pipeline, but the new `run_offsite_dppa` already delegates to the case builder via a registry — inverting it would be circular without first MOVING the orchestration into the new package. Don't force the inversion in the same cycle if it risks proven parity + existing tests; ship the front door + deprecate via docs, and stage the code-move. A runtime `DeprecationWarning` on a function the new layer itself calls will fire during normal operation and pollute tests — deprecate via docstrings until the call path no longer routes through it.
- 2026-06-12: "Compatibility shims" can be load-bearing — removing them is not cosmetic. The flat `scripts/python/*.py` layer was 86% thin shims but 14% (7 files, 115–404 lines) were real implementations with no canonical twin (relocate, never delete). Worse, tests imported the moved modules through the flat layer: 7 tests did `sys.path.insert(scripts/python)` + `from <name> import ...` or a subprocess to a flat path, and broke when the shims went. Rules: (1) classify each file (twin-exists + small = shim → delete; else real → `git mv`); (2) after ANY structural move, run the FULL test suite, not a subset — `--collect-only` is not enough and a subset (reopt/ingestion) missed integration-test breakage; (3) when a numeric test fails after a refactor, prove cause vs pre-existing by running it at the prior commit in a `git worktree` before assuming it's yours.
- 2026-06-12: Scoped `.gitignore` negations precisely. A broad `!reports/*sprint-*.html` meant to keep repo-trim reports accidentally re-tracked unrelated `2026-05-19-validation-sprint-*.html`. Anchor negations to the specific work (`!reports/2026-06-12-sprint-*.html`) and `git status` after, since `git add -A` will silently re-stage anything a loose negation un-ignores.
- 2026-06-12: Before deleting a directory, grep for the BARE directory name (e.g. `archive`), not the path form `archive/`. Tests/code build paths from segments like `REPO_ROOT / "archive" / "colab" / ...`, which `grep "archive/"` never matches. The Sprint 1 de-bloat deleted `archive/` after a clean `archive/` grep, but `tests/python/reopt/test_api_result_sanitization.py` loaded `redact_sensitive_fields` from `archive/colab/.../run_colab_api_reference.py` via path segments — caught only by running the tests. Rule: (1) grep bare names; (2) a directory with a live test dependency is not dead — relocate the depended-on code into canonical `src/` rather than restoring the archive; (3) always run the test suite in the verification phase, never assume a "pure deletion" is safe.
- 2026-09-02: When a script's only failure mode is a missing input path, grep for every idiom that builds that path, not just the first one you find. Repointing the 20 report emitters that used `Path.home()` left five more broken ones that reached the same missing template through `os.path.expanduser("~/.config/opencode/...")` behind a CWD-dependent relative fallback — found only by grepping the vendor name (`opencode`) rather than the API (`Path.home()`). Rule: grep the *value* (the distinctive path segment), not the *call*, when hunting external dependencies. Same shape as the 2026-06-12 "grep bare directory names" lesson.
- 2026-09-02: Verifying that a report generator "runs" writes its report, and a repo mid-reorganization will silently accept those writes at the old paths. Running the 25 repointed emitters re-created 29 HTML reports at `reports/<date>-*.html` that the pending working-tree change had moved to `reports/archive/YYYY-MM/` — invisible unless you check `git status` for untracked output afterwards, because `reports/*.html` is NOT git-ignored (AGENTS.md claims it is; only `reports/*.html.txt` and `reports/decks/` actually are). Rule: after running any generator as a verification step, `git status --porcelain` and remove the byproducts; and do not trust a doc's claim about what is ignored — ask `git check-ignore -v`.
- 2026-09-02: Prove a "duplicated helper" is really equivalent before unifying, because the divergence may be latent rather than active. Samsung's `_calibrate_to_target` was a single-pass redistribution over ALL hours while the generic S2 one was daylight-only and iterative — genuinely different functions — yet they returned bit-identical series on Samsung's real inputs because the redistribution branch never fired there (deficit <= 1.0). Running the exploratory diff first turned a scary golden-moving refactor into a provably value-preserving one. Corollary: a parameter can be inert (Samsung's `reference_year` could not change the synthetic shape, since hour-of-day and day-of-year both run 1..365 over the first 8760 hours of any year); check before preserving it in the new interface.
